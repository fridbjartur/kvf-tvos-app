# Android / Google TV

KVF uses the same React Native TV app and scraper API on Apple TV and Android / Google TV. The Android TV version follows the Apple TV app: a top tab bar that selects tabs as focus moves and scrolls away with the content, smooth focus scrolling, fullscreen playback with TV-specific Media3 controls, radio, episode queues, and persistent on-device watch history. See [TV navigation](tv-navigation.md#android-tv) and [Android TV controls](playback.md#android-tv-controls).

## Development setup

Install Android Studio, the Android SDK Platform 36 and Build Tools 36, and a compatible JDK (17 works with this project). In Android Studio's SDK Manager, install an **Android TV** system image, then create a **TV** device in Device Manager. On Apple silicon, choose an ARM64 image. A phone emulator does not validate remote navigation.

On macOS, configure your shell:

```sh
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH"
```

Install project dependencies with `yarn install --frozen-lockfile`. Set `EXPO_PUBLIC_KVF_API_BASE_URL` in `.env.local` to your scraper API. The TV must be able to reach it. For an API running on the development Mac, the Android emulator can use `http://10.0.2.2:3000`; a physical TV can use a reachable LAN address, a deployed server, or the localhost forwarding described below. The address is public and embedded at build time; changing it requires a rebuild for an APK.

Start your TV emulator, then run:

```sh
yarn prebuild:android:tv
yarn android:tv
```

The Android-only prebuild regenerates `android/` with `--clean`. Keep customizations in Expo config/plugins; local edits inside `android/` will be replaced. It does not regenerate `ios/`.

## Standalone tester APK

From the repository root:

```sh
yarn android:tv:apk
```

This regenerates Android only and builds a release-mode APK with its JavaScript and assets bundled. The output is `dist/kvf-android-tv.apk`. It uses Expo's generated development signing key for local testing, and is not a store submission build. Keep this key if distributing future updates to the same testers. The first build downloads native dependencies and can take several minutes.

Install on a connected emulator or TV with:

```sh
adb devices
adb -s DEVICE_SERIAL install -r dist/kvf-android-tv.apk
adb -s DEVICE_SERIAL shell am start -n dev.fridbjartur.kvf/.MainActivity
```

For a physical TV, enable developer options and its supported USB/network debugging method. Pair/connect it using the address and port shown by that device; then use its serial from `adb devices`. Alternatively, transfer the APK and install it with a file manager after allowing that installer to install unknown apps.

If you keep `EXPO_PUBLIC_KVF_API_BASE_URL=http://localhost:3000`, run this after connecting each test device:

```sh
adb -s DEVICE_SERIAL reverse tcp:3000 tcp:3000
```

Keep the local API running on the Mac. This maps the device's localhost to the Mac's port 3000 and depends on the ADB connection. Use the actual port from your API setting if it differs. A deployed API or reachable LAN address avoids this forwarding requirement.

The APK runs without Metro. It can also run without the development Mac when its API and KVF streams are independently reachable. Stop Metro and relaunch from the TV's app launcher to check this.

`plugins/withAndroidTV.js` also installs the TV playback controls from `plugins/android-tv-res/`, so changes there need a prebuild. Android release networking permits HTTP only for the KVF radio host (`netvarp.kringvarp.fo`) and the configured HTTP API host. HTTPS remains available for other hosts. This policy and the landscape/launcher artwork settings are generated by `plugins/withAndroidTV.js`. Android watch history lives in the document directory; catalog cache eviction should not remove it.

## Verification status

On 2026-10-09 the debug build and the standalone release APK were checked on the ARM64 Android TV API 36 emulator (720p) with the local API: focus-driven tab switching, Back to the tab bar and out of the app, the tab bar scrolling away, smooth vertical snapping and flash-free shelf scrolling, hero Left/Right, the full-width search grid, schedule rows, Ljóð category open/close (with focus returning to the chosen card and staying on the bar when the tab is selected), focus restored to the opening card after program and player round trips, the TV playback controls (play/pause focus, 10-second seek, scrubbing, subtitle/settings menus), and Up Next above the scrubber. These emulator checks do not replace the physical-device checks below.

The standalone release APK was first built and installed on an ARM64 Android TV API 36 emulator on 2026-10-02. It ran with bundled JavaScript and the localhost API forwarded over ADB. Emulator checks confirmed top-tab focus, catalog/program navigation, the system search keyboard and filtered results, HLS episode playback, native play/pause and seeking, live TV, automatic episode advance, and Continue Watching/resume after force-stopping and relaunching the app. The port fixes Android's HLS format inference for KVF redirect URLs and makes the search input selectable by remote.

TypeScript, non-mutating ESLint, formatting, and all 24 Jest suites (281 tests) passed. Regression coverage includes Android tab navigation, search focus, HLS source selection, Up Next focus requests, Android history persistence, and native configuration.

Physical Android / Google TV testing and Apple TV hardware regression checks remain required before calling this version ready. Selecting Up Next with the final remote focus behavior, audible radio output, complete network-disconnect/retry testing, and an exhaustive remote pass on every screen remain acceptance checks; this headless emulator run does not establish them.

## Remote and playback acceptance checks

- Move along all six tabs: each tab is selected as it gains focus, without Select. Move down into content and up into tabs. Check focus visibility and smooth scrolling on shelves, search results, radio categories, schedule rows, and program episodes; moving to an off-screen card must not flash.
- Scroll down a screen: the tab bar scrolls away. Back scrolls to the top and focuses the current tab; Back again leaves the app. Up from the first row reaches the tabs only after the screen returns to its top.
- Search using the system keyboard; dismiss it with Back and navigate results. Switch tabs and return: the query persists and results scroll to the top.
- Enter a radio category: its first card takes focus. Switch tabs and return; the category is preserved. Back returns to its picker with the chosen card focused; Back from program/player returns one screen. Selecting Ljóð from the tab bar keeps focus on the bar.
- On a hero banner, Left/Right change one slide per press.
- Play episodes, live TV, and radio. Playback is fullscreen with play/pause focused; there is no fullscreen or previous/next button. Check play/pause, 10-second rewind/fast-forward, scrubbing, and available audio/subtitle tracks. Up Next must be reachable with arrows and Select without taking focus from scrubbing when it appears. Check automatic episode advance.
- Pause or close an episode after at least ten seconds. Relaunch: Continue Watching and program Resume restore progress. Check Start Over and completion; live streams should not enter history.
- Disconnect networking: cached catalog remains usable, playback failure offers Retry, and reconnecting recovers. Backgrounding pauses playback without automatically resuming it.
- Test the standalone APK on a physical Android / Google TV device. Emulator results do not establish physical remote, decoder, or sleep behavior.
- After shared UI/player changes, check Apple TV native tabs, search, resume, seeking, Up Next, and Menu navigation on Apple hardware.

Run automated checks with:

```sh
yarn typecheck
yarn lint:check
yarn test --runInBand --watchman=false
```

Samsung Tizen, LG webOS, Fire TV validation, and public store submissions are outside this first Android / Google TV delivery.
